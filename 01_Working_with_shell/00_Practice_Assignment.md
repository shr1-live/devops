# Practice Assignment: Working with the Shell

A daily drill for everything in this section. **Do not edit this file.** Do the tasks from memory, then write the commands you used in a log file (see [How to submit](#how-to-submit)).

Covers: [[01_Intro_to_shell]], [[02_Basic_linux_commands]], [[03_Paths]], [[04_Shell]].

## Rules

1. Try every task **from memory first**. Only open the notes (or `man` / `--help`) when you are stuck, and mark that task with `(looked up)` in your log.
2. Do everything inside the Docker practice container, never on your host machine. See the README for how to start it.
3. Keep all your work inside `~/shell_practice`, so cleaning up is one command.
4. Whenever you **add a line** to `~/.profile` or `~/.bashrc`, end it with the comment `# practice`. Example: `alias x=y   # practice`. The [cleanup step](#task-10-clean-up-for-tomorrow) uses this marker to remove only your practice lines.
5. Aim to finish in under 30 minutes. Write down your time in the log and try to beat it.

## Start

```bash
docker compose up -d                 # from the repo folder on your host
docker compose exec ubuntu bash      # open a shell in the container
```

## Task 1: Built-in or external?

Notes: [[01_Intro_to_shell]]

1. For each of these commands, find out whether it is a shell built-in or an external program: `echo`, `cd`, `pwd`, `pushd`, `mv`, `date`, `uptime`.
2. For the external ones, print the full path of the program file.
3. Print the list of directories the shell searches for external commands.

**Check:** you should see `is a shell builtin` for 4 of them and a path like `/usr/bin/...` for the other 3.

## Task 2: Build a directory tree

Notes: [[02_Basic_linux_commands]], [[03_Paths]]

Create this structure inside `~/shell_practice/world` using as **few `mkdir` commands as possible** (one is enough):

```text
world/
├── Asia/
│   ├── India/Mumbai/
│   └── Japan/Tokyo/
├── Europe/
│   └── Morroco/          <- wrong continent AND a typo, on purpose
└── Africa/
    └── Egypt/Cairo/
```

1. Create it.
2. Create an empty file `city.txt` inside `Mumbai`.
3. Write the line `Mumbai is in India` into `Mumbai/city.txt` **without opening an editor**, then add a second line `Population: 20 million` to the end of the same file.
4. Print the file to check that both lines are there.

**Check:** the file shows exactly 2 lines. If it shows only 1, you overwrote instead of appending.

## Task 3: Move, rename, copy, delete

2. Rename it to `Morocco` (fix the typo).
3. Copy `Mumbai/city.txt` into `Egypt/Cairo/`.
4. Copy the whole `Japan` directory into `Europe` (yes, it's wrong, it's for practice).
5. Delete the `Japan` copy you just made inside `Europe`.
6. Delete `Europe` itself using the command that **only works on empty directories**.
7. List `Asia` in long format, including hidden files.
8. List `Asia/India/Mumbai` sorted by modified time, oldest first.

**Check:** `Europe` is gone, `Africa` contains `Egypt` and `Morocco`, and `Cairo` contains `city.txt`.

## Task 4: Paths and the directory stack

## Task 6: Shell variable vs environment variable

Notes: [[04_Shell]] (Bash Environment Variables)

This is the most important task. Use the helper program below to **see** the difference.

**Setup (given, not part of the drill):** create a tiny program in `~/shell_practice/bin`:

```bash
mkdir -p ~/shell_practice/bin
cat > ~/shell_practice/bin/hello-devops     # type the 2 lines below, then press Ctrl+D
#!/bin/bash
echo "Hello from [$LAB_NAME], I am $USER"
chmod +x ~/shell_practice/bin/hello-devops  # make it executable (permissions come later)
```

Now the drill:

1. Print your home directory, username, current shell and current directory, using **variables only** (no `pwd`).
2. Create a **shell variable** `LAB_NAME` with the value `devops-lab`. Print it.
3. Run the helper by its full path. Does it see `LAB_NAME`?
4. Search the list of **environment variables** for `LAB_NAME`. Is it there?
5. Turn `LAB_NAME` into an **environment variable**. Repeat steps 3 and 4.
6. Remove the variable completely and run the helper once more.

**Check:** in step 3 the helper prints `Hello from []`, in step 5 it prints `Hello from [devops-lab]`. Write one sentence in your log explaining why.

## Task 7: PATH

Notes: [[04_Shell]] (PATH Variable)

1. Try to run `hello-devops` by **name only**. Note the error.
2. Check which file the shell would run for `hello-devops`. (No output means "not found".)
3. Add `~/shell_practice/bin` to the **end** of `PATH` for this terminal, **without losing** the directories already in it.
4. Run `hello-devops` by name again, and show where the shell found it.
5. Open a new shell with `bash`, run `hello-devops` there, then `exit`. Did it work? Why?

**Check:** step 3 must not break `ls`. If `ls` stops working, you replaced PATH instead of appending. Run `exit` and open a new container shell to recover.

**Think (answer in your log):** what would happen if you put the new directory at the **start** of PATH and it contained a program named `ls`?

## Task 8: Make it permanent

Notes: [[04_Shell]] (`~/.profile` and `~/.pam_environment`)

1. Make `LAB_NAME=devops-lab` **and** your PATH change permanent by adding them to `~/.profile`. Remember the `# practice` marker on each line.
2. Load the file into your current shell without logging out.
3. Verify from a **brand-new login shell** that both work. Do it in one line, without staying in the new shell.
4. Now try the same check with a **non-login** shell (plain `bash`). What do you see?

**Check:** step 3 prints `Hello from [devops-lab]`. In step 4, a new container shell (`docker compose exec ubuntu bash`) is a **non-login** shell, so it does **not** read `~/.profile`. Write down which file a non-login interactive shell reads instead.

## Task 9: Prompt, alias, history

Notes: [[04_Shell]] (Features of Bash Shell, Bash Prompt)

1. Print the current prompt format.
2. Change the prompt so it looks like `[dev@devops-lab Mumbai]$ ` (username, hostname, **only the last folder**).
3. Change it again to also show the time in 24h format at the start: `14:05:09 [dev@devops-lab Mumbai]$ `.
4. Make the prompt from step 2 permanent for every new terminal, and load it without opening a new terminal.
5. Create an alias `now` that runs `date`. Make it permanent the same way.
6. Show your command history, then rerun one earlier command **by its number**.

**Check:** open a new container shell (`docker compose exec ubuntu bash`). The new prompt and `now` should both work.

## Task 10: Change your login shell

Notes: [[04_Shell]] (Change shell)

1. List the shells allowed on this system. Is `zsh` there?
2. Install zsh: `sudo apt-get update && sudo apt-get install -y zsh` (given). List the allowed shells again.
3. Print your current default shell from the variable.
4. Change the default login shell of user `dev` to zsh.
   - Hint: plain `chsh` asks for your password, and `dev` doesn't have one. Use the root version of the command and pass the username.
5. Verify the change by reading **dev's line in the user database** (`/etc/passwd`). Don't trust `$SHELL` here, it only updates after a new login.
6. Start a new **login** session as `dev` and confirm which shell is running (`echo $0`).
   - Hint: `sudo -iu dev`. If zsh shows a setup menu the first time, press `q`.
   - `docker compose exec ubuntu bash` always starts bash because you named `bash` in the command, so it can't be used to check this.
7. `exit` back, then change the login shell back to `/bin/bash` and verify again.

**Check:** step 5 shows a line ending in `/bin/zsh`, step 7 a line ending in `/bin/bash`.

## Task 11: Clean up for tomorrow

Do this at the end so you can repeat the whole assignment fresh tomorrow.

```bash
cd ~
rm -rf ~/shell_practice
sed -i '/# practice$/d' ~/.profile ~/.bashrc   # remove only the lines you marked
sudo chsh -s /bin/bash dev                      # in case Task 10 step 7 was skipped
exit
```

Then open a new container shell and check that `hello-devops`, `now` and `$LAB_NAME` no longer exist.

For a completely clean machine instead (this also erases your shell history), run on the host: `docker compose down -v && docker compose up -d --build`.

## How to submit

1. Copy `practice_log/_template.md` to `practice_log/YYYY-MM-DD.md` (today's date). Don't edit the template.
2. Paste the commands you used for each task into the matching section. Paste **commands only**, not the full output, except where a task asks a question.
3. Mark any task you had to look up with `(looked up)`.
4. Ask Claude: _"review my shell practice log for today"_. You will get the mistakes, shorter alternatives, and the tasks to focus on next time.

> [!tip]
> Your history is a quick way to collect the commands: run `history | tail -n 100` in the container before you clean up, and copy what you need from there.
